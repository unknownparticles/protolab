# 需求拆解与实现计划

## 目标与技术决策

以用户提供的单文件原稿和设计要求为基础，交付可维护、纯静态、可部署的原型设计器。原稿保存在 `reference/original.html`；需求原文保存在 `design-requirements.md`。

「拆解完善」优先于原需求中的单文件源码要求。编辑器拆成原生 ES 模块与样式文件，运行无需编译；导出的原型仍是单个完整 HTML。用本地 SVG 图标替代 Font Awesome CDN，避免离线图标缺失。用非阻塞消息反馈和可编辑弹窗替代 alert / prompt，文件覆盖保留明确确认。

## 原稿问题与修复

| 原稿问题 | 完善方案 |
| --- | --- |
| mousedown 选中时重建节点，拖动事件仍引用已脱离文档的节点 | 节点按标识复用，选择只更新状态，移动使用指针捕获 |
| `dropX || 50`、`radius || 8` 丢失零值 | 明确数值校验，零坐标和零圆角有效 |
| 画布减去猜测的 36 px 标题高度，预设与导出尺寸不符 | 标题放到画布外，模型统一保存实际内容尺寸 |
| 自定义尺寸只约束最小值，旋转恢复旧预设 | 上下限 100～2000；旋转直接交换当前宽高 |
| 组件大于画布时位置可能变负，缩小后组件越界 | 尺寸先适配画布，再约束非负位置 |
| 「保存」只写 localStorage，无 JSON 导出入口 | 区分保存、导出与导入，支持版本化 JSON 和旧数组 |
| SVG / 名称 / HTML 导入直接拼接，导出名称未转义 | 内容静态化清理、名称转义、字段和容量校验 |
| 存储异常被吞掉，仍提示保存成功 | 仅成功时提示已保存，失败说明数据仍在内存并可导出 |
| 放置坐标未考虑缩放 | 坐标与移动增量除以当前 zoom |
| 修改未保存画布草稿 | 自动保存、刷新恢复、离开前刷新存储 |
| 输入框不可选择文字、模态输入体验有限 | 移除全局 user-select 禁用，使用命名、尺寸和代码表单 |

## 验收映射

原要求中的手机／平板／PC、旋转、拖拽选中、命名标签、HTML／SVG／图片创建、组件库保存导入导出、属性调整、独立 HTML 导出和纯静态部署均有对应实现。发布工作流准备完成；用户已授权提交并发布到 `unknownparticles/protolab`，部署与验证纳入本次交付。

导出的组件外框与画布展示共用代码，浏览器验收对尺寸、圆角、边距、背景、阴影等逐项比较。自定义内容经过静态化处理，因此「100% 还原」指编辑器实际显示的静态组件，与任意原始网页的脚本、外部 CSS 或动态效果不同。

原稿未实现的缩放、草稿、历史、图层排序、点击添加、复制、键盘微调和小屏折叠作为本轮完善一并交付。后续仅安排尚未实现的功能。

## 后续迭代

1. 浏览器兼容性：Firefox / Safari / Edge 手工拖放、文件导入与导出验收；低性能设备帧率测量。
2. 编辑体验：拖拽尺寸手柄、多选、对齐参考线、吸附、辅助网格。
3. 数据能力：原型项目 JSON 备份／恢复、导入合并策略、自定义组件删除与编辑。
4. 结构能力：容器嵌套、响应式断点与模板。
5. 高级能力：React / Vue 导出、暗色主题、团队云端同步。

团队同步需要后端，独立拆成另一个阶段。组件嵌套需要新增树状模型，不直接拼进当前绝对定位列表。
